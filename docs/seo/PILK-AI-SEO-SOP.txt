  Run this on every site we own. Phases 1 to 4 set the foundation and get the site into every
  search engine and AI answer engine, and fit in one working day with Claude and the
  owner working side by side. Phases 5 to 8 keep it growing. Every step says who does it
  and how to check it worked.


  How to use this
  Claude does the code, the settings pages and the checks. The owner does the parts no AI
  is allowed to do: creating accounts, typing passwords, approving Google or Microsoft
  sign-in screens, solving CAPTCHAs, and saying yes to anything that changes DNS or
  account settings.

         Claude can: edit and deploy the site, open dashboards the owner is already signed
         into, add properties, submit sitemaps, request indexing, run speed and tag checks,
         write content.
         Owner must: create every new account (Bing, Google Business Profile, Apple, Yelp,
         socials), sign in, click through any "Allow access" screen, verify by postcard or video,
         and give an explicit OK before a DNS or nameserver change. Claude's own safety
         check can still block a DNS edit even after an OK. Then the owner clicks it, with
         Claude giving the exact steps.

  Phase 1: Technical foundation
  Get one clean, fast, crawlable version of every page before telling any search engine
  about the site.




                                                                                                Page 4 of 24
PILK AI SEO SOP




         One host. Pick www or bare as the main host. 301 everything else to it, keeping the
         path and query string. Test http:// , https:// , bare, www, and a deep path with ?
         utm_source=test . Registrar forwarding (GoDaddy, Namecheap) usually drops paths,
         so use a Cloudflare Redirect Rule instead.
         HTTPS everywhere. Turn on Cloudflare "Always Use HTTPS", set SSL to Full or Full
         (strict), and send an HSTS header from the site.
         robots.txt. Allow everything public. Block only admin, API, internal redirect and cart
         paths. List the sitemap with its full URL. Never block CSS or JS.
         Sitemap. List every indexable page and nothing else (no redirects, 404s or noindex
         pages). Use a real lastmod from when content changed, plus image and video entries
         where the page has them. Split it past 50,000 URLs.
         Canonical tag on every page, pointing to itself on the main host.
         Titles and descriptions. Make each one unique. Title about 50–60 characters, saying
         what people actually search, brand last. Description about 140–160 characters that
         make someone click.
         One H1 per page, saying what the page is. Headings in order below it.
         Open Graph and Twitter card tags with a 1200×630 image, so shared links look right.
         Structured data (JSON-LD).
                  Organization (logo, sameAs social links) and WebSite on every page.
                  Then the type each page really is: LocalBusiness (or a subtype) with address,
                  phone and hours; Product with price and availability; Article or BlogPosting with
                  author and dates; BreadcrumbList; ProfilePage or Person; Service; FAQPage only
                  for questions shown on the page.
                  Check with Google's Rich Results Test and the Schema.org validator.
         Hide staging and preview copies. Send X-Robots-Tag: noindex on *.pages.dev ,
          *.vercel.app , *.netlify.app and preview branches, or password-protect them.
         llms.txt at the root: a short plain-text guide to the site and its key pages, for AI tools.
         An llms-full.txt with the full detail is optional.
         Real 404s. Missing pages return status 404, not 200 or a redirect to the homepage.
         Speed and Core Web Vitals. Targets: LCP under 2.5 s, INP under 200 ms, CLS under
         0.1. Run Lighthouse on mobile for the homepage and one page of each template. Fix in
         this order: images (WebP or AVIF, sized, lazy below the fold), render-blocking scripts,
         then unused JavaScript.
         Mobile. No sideways scrolling at 360 px, tap targets at least 44 px, and text readable
         without zooming.

         Internal links. Every page reachable within 3 clicks of the homepage, with descriptive
         link text and no orphan pages.
         Languages. If the site serves several, add hreflang tags and a separate URL per
         language.
         Adult or regulated sites. If pages carry explicit content, add <meta name="rating"
         content="adult"> , since Google expects it for SafeSearch. Non-explicit pages can
         leave it off. Don't plan on Google Ads for adult offers.

  Bing Places, Apple Business and video verification
  Bing and Apple don't work like Google. Notes from the Nov 2026 setups:

         Bing Places: import needs a verified Google profile. "Import from Google" only works
         once the Google Business Profile is verified. Otherwise create the listing by hand.
         Bing Places: mailed PIN, edits locked. Verification is a mailed PIN only, 5–6 business
         days. Hours, description, photos and hiding the address all stay locked until the PIN is
         entered, so request it on day one.
         Bing Places: finer categories. Bing has more specific categories than Google (for
         example "Real estate photography"). Pick the most specific one that fits.
         Apple Business (was Apple Business Connect): Maps needs a walk-in location. An
         Apple Maps place card can't hide the address, so skip Maps for home-based
         businesses.
         Apple Business: brand-only setup. Branded Mail, the Tap to Pay logo and business
         caller ID work without a location. Sign up with a Managed Apple Account.
         Apple Business: organization verification needs two methods. Domain validation can
         fail with "Unable to add domain" when the domain is tied to another Apple account.
         Then upload the state filing (Articles of Organization) under "Other". The owner
         enters the EIN under Business ID personally.

         Apple Business: one organization per LLC. A separate LLC gets its own organization,

         Google video verification for a home-based service-area business. The owner

            1. Street signs or landmarks near the address. No unit number or interior needed.

  BBB, Nextdoor and Yelp
  Google is one listing; BBB, Nextdoor, Apple, Yelp and Bing are the next five. Most owners
  never claim them.

         BBB: free listing, skip accreditation. Start at bbb.org/get-listed. It creates a free BBB
         account and profile. Accreditation is the paid extra and isn't needed. Ask BBB to hide
         the street address for a home-based business.
         Nextdoor: hangs off a personal account. The business page belongs to the owner's
         personal Nextdoor account. It needs an address to place the business in a
         neighborhood. A home address is fine: leave "Show above address" unchecked to
         keep it hidden.
         Yelp: service-area setup. Set the service area and hide the address. Verification is a
         call or text to the business phone, so the owner does it.

  What changed in 2026
         Owners choose which photos show first. Lead with the best real job photos.
         AI flags fake reviews. Google emails the owner when fake reviews are removed. Don't
         buy reviews or gate them.
         AI-drafted Q&A. Google drafts answers to customer questions from the profile, the
         website and reviews. The owner approves, edits or rejects each draft before it goes
         live (PinMeTo, Jun 2026).
         Freshness and engagement count more. Practitioners report that a profile with no
         new photo or post for about 30 days slips in local rankings, and that weight is moving
         toward review speed, response time and engagement. Treat this as field experience,
         not a Google statement. The core habit is simple: one real photo and one short post
         every week, treating the profile like a maintenance schedule.


  The 15-minute weekly routine (every Monday)
         Post one short update about a job you just finished, naming the service and the town
         ("kitchen remodel in New Canaan"), with a real photo from that job. Two a week is
         better.
         Upload at least one new real photo or short video. Phone shots are fine; they just have
         to be real. Check which photos show first.
         Reply to every new review within 48 hours, negative ones first. Use the customer's
         name and the service.
         Clear the AI Q&A queue: approve or fix every draft answer.
         Check for edits Google or the public suggested (hours, categories, phone) and reject
         wrong ones.
         Send review requests to last week's happy customers by text or email, with the direct
         review link.
         Glance at the Performance tab: calls, direction requests, website clicks against last
         week.

  Rules that keep Google on side
         No mass-produced filler. Google's spam policy calls it "scaled content abuse". AI can
         draft, but a person who knows the business checks every fact and adds something
         only the business knows.
         No doorway pages. Don't build near-copies for every city with only the name
         swapped. A city page needs real local proof: jobs done there, local photos, reviews
         from there.
         Real authorship and dates. Each article shows an author, when it was published and
         when it was updated. Refresh the top pages every quarter.
         Internal links. Every new page gets 3+ links from related pages, and links out to the
         money page it supports.

  Phase 6: Authority and links
  Links from real, relevant sites are still the strongest outside signal, for Google and for AI
  engines deciding whom to trust. Start with links you control, then the ones you can earn.


  Day one: links you control
         Brand profiles on LinkedIn, X, Instagram, Facebook, YouTube, TikTok, Pinterest, Reddit,
         Crunchbase and Medium. Each links back to the site and goes into the site's sameAs
         list.
         Owners, partners and team: link the site from personal bios, email signatures, other
         businesses you own and client sites ("Website by" credits).
         Everything you already publish (social bios, link-in-bio pages, YouTube descriptions,
         newsletters) points to the right page on the site.

  Running the free dofollow list (Nick Nolan list + gap prompt)
  Works for any business, not just software. Claude does the research and writes the copy.
  The owner approves each batch and keeps every login.

     6. Add 10–15 a week, not all at once. Re-check link types quarterly, because these lists go

  Internal links with a site: search
     1. For the page you want to push, search Google for site:yoursite.com "keyword" .
     2. Every result that talks about that topic without linking to it gets a link, wrapped
        around words already in the sentence. No new sentences.
     3. At most 2 new links per page, varied anchors, never "click here".
     4. Crawl the built site from the homepage afterwards: nothing deeper than 3 clicks, no
        broken links.

  Done 16 Nov: Rendprop 107 links in 104 posts (live), WML 59 links on 49 pages (merged,
  not deployed yet), pilk.ai 16 links (live).


  Objection pages from Reddit
     1. Search site:reddit.com "[category]" "waste of money" , then the same with
         "worth it" and "scam".
     2. List the objections that repeat across threads. Paraphrase them; never quote.
     3. Write one "Is [service] worth it?" page: a two-sentence answer up top, one H2 per
        objection, a "when to skip it" section. Every rule or law cites a primary source.
     4. Link it from the matching service page and 2 or 3 related posts, then request indexing.

  Reddit blocks automated reads, so find the threads through search and news write-ups
  that summarise them. Live: rendprop.com, pilk.ai. WML's broker page is rewritten and
  waiting on the deploy.

  Gotchas we hit on Rendprop and WSM Lending (Nov 2026)
  Each of these cost time on Nov 12, 2026, on rendprop.com, wsmlending.com (WML) and
  the Rendprop and Pilk Consulting listings. The fix follows each one.

         Check the Google account before every Google action. Chrome had several Google
         accounts signed in, and a property went under the wrong one. The cleanup meant
         deleting a stray verification TXT record and removing an unverified property. Read the
         account email under the avatar first, then pin the URL with /u/N or authuser=N .
         Cloudflare's AI crawler policy can override robots.txt. AI Crawl Control "Training:
         Disallow" was blocking GPTBot, ClaudeBot and Claude-User even though the site's
         robots.txt allowed them. Check Cloudflare, not just robots.txt, and confirm with a
          curl as each bot's user agent.
         www returning 522 means a proxied www record with nothing behind it. Fix it with
         a Single Redirect: https://www.domain/* → https://domain/${1} , 301, preserve
         query string. Cloudflare's wildcard needs an explicit scheme: *:// is rejected. Turn

         on Always Use HTTPS so http://www is caught first. Check with curl -I on www
         plus a path and a query.
         Don't add a domain-to-domain redirect before the code deploy. On WML, the live
         app still 308'd non-root paths to the old domain, so a Cloudflare redirect the other way
         would have looped. Deploy the code first, then add the redirect.
         Cloudflare Web Analytics "automatic setup" injects on every path, customers'
         hosted pages included. A strict CSP silently blocks it, so you get 0 page views. Use
         manual snippet mode on the marketing pages only, add the two Cloudflare hosts to
         that CSP ( static.cloudflareinsights.com in script-src, cloudflareinsights.com
         in connect-src), and update the privacy policy in the same deploy.
         The privacy policy must match the analytics. If it says "no third-party analytics",
         adding analytics without a policy change makes a false statement. The owner decides.
         Deploys from a cloud session can't reach Cloudflare credentials. Ship an owner-run

                  checks the live version first and fails closed on any other state;
                  records the rollback version;
                  runs live checks after the deploy;
                  submits IndexNow.
         If another session has uncommitted work on the Mac, the script refuses to run until
         that work is merged.
         Google Business Profile photo upload runs in a cross-origin frame that the browser

         Bing Places can't import an unverified Google profile, and the PIN locks every edit.
